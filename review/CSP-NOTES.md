# Content-Security-Policy — notes & enforce-flip checklist (2026-07-18)

## What ships now
A **hash-based CSP delivered as `Content-Security-Policy-Report-Only`** in `vercel.json`
(catch-all `/(.*)` header block), generated by `scripts/generate-csp.mjs`.

Directives:
- `default-src 'self'`
- `script-src 'self'` + **18 sha256 hashes** — one per inline `<script>` in `index.html` (7) and
  `install.html` (2), each emitted in **both LF and CRLF** variants so the policy is correct
  whether served with Linux (Vercel build) or Windows (local) line endings. `'self'` covers
  `assets/app.js` and the Vercel Insights loader at `/_vercel/insights/script.js`.
- `style-src 'self' 'unsafe-inline'` — index.html uses inline `style="…"` attributes, which
  cannot be hashed. (`<style>` blocks could be hashed, but attribute styles force `'unsafe-inline'`.)
- `img-src 'self' data: blob:` — `/assets`, `/cdn` (same-origin), canvas `data:`, share `blob:`.
- `connect-src 'self'` — `/api/*` and the Vercel Insights beacon (`/_vercel/insights/view`) are same-origin.
- `font-src 'self'`, `worker-src 'self'`, `manifest-src 'self'`, `base-uri 'self'`,
  `object-src 'none'`, `frame-ancestors 'none'` (matches `X-Frame-Options: DENY`), `form-action 'self'`.

## Proven in a real (headless Chromium) browser
- Inline-script hashes are correct: served **enforcing**, all inline scripts execute
  (`window.va` is defined by the Insights stub, `#headline`/`#temp` populate) with **0** console
  CSP refusals on home. Served **Report-Only**, **0** `securitypolicyviolation` events across
  home + SPA screens + `/install`, at 1440px and 390px.
- A prior bug was caught and fixed: hash sources were emitted **unquoted**; CSP requires
  `'sha256-…'` (single-quoted), else Chromium parses them as invalid host sources and ignores
  them (every inline script then blocked). `tests/csp.test.js` guards against this regression.

## Why Report-Only, not enforcing (this session)
Three surfaces cannot be exercised in a local headless harness, so per the ruling
"never ship a policy that breaks the app," enforcing is not flipped yet:
1. **The real Vercel Insights beacon** (`/_vercel/insights/*`) is injected only in production.
2. **PWA install / Web-Share intents** depend on the real platform.
3. **The install-page QR is an EXTERNAL image** — `install.js` renders
   `<img src="https://api.qrserver.com/…">` in the desktop "open on your phone" flow. The strict
   `img-src 'self' data: blob:` (the ruled "self + Insights only" source list) **reports/blocks it.**

## Open finding (owner decision required before enforce)

(b) keeps the source list at "self + Insights". Logged, not fixed (no scope additions this session).

## Regenerating hashes
Inline scripts changed? Run `node scripts/generate-csp.mjs --write` and commit `vercel.json`.
`tests/csp.test.js` fails if `vercel.json` is stale, so drift can't ship silently.
