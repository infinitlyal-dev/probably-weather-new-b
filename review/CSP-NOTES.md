# Content-Security-Policy — notes (ENFORCED 2026-09-15)

## What ships now
- **`Content-Security-Policy` — enforced**, in the catch-all `/(.*)` header block of `vercel.json`,
  generated by `scripts/generate-csp.mjs`.
- ~~The identical policy as `Content-Security-Policy-Report-Only`~~ — kept alongside for the first
  week (until 2026-09-22), **dropped 2026-09-24**: `KEEP_REPORT_ONLY = false`, `vercel.json`
  regenerated. It was still live on production two days late, and WebKit logged
  "The Content Security Policy directive 'frame-ancestors' is ignored when delivered in a
  report-only policy" on every page load (launch eval walk, all five WebKit phone runs).
- Both carry **`report-uri /api/csp-report`**. `api/csp-report.js` logs one `[pw-csp]` line per
  violation — enforced ones at error level (they reach the Vercel runtime error table), report-only
  at warn. Every URL is cut to path + lang + condition; script samples are never logged. Reports
  about pages that are not ours are dropped; same per-IP bucket as `/api/errors`.

Directives:
- `default-src 'self'`
- `script-src 'self'` + **19 sha256 hashes**: the 7 inline `<script>`s in `index.html` and 2 in
  `install.html`, each in **LF and CRLF** variants (18), plus the **`/share` redirect** script
  (`api/_lib/share-redirect.js`). `'self'` covers `assets/app.js` and `/_vercel/insights/script.js`.
- `style-src 'self' 'unsafe-inline'` — inline `style="…"` attributes cannot be hashed.
- `img-src 'self' data: blob: https://api.qrserver.com` — same-origin images, canvas `data:`,
  share `blob:`, and the `/install` page's QR code.
- `font-src 'self' data:`, `connect-src 'self'` (`/api/*` and the Insights beacon are same-origin),
  `worker-src 'self'`, `manifest-src 'self'`, `base-uri 'self'`, `object-src 'none'`,
  `frame-ancestors 'none'` (matches `X-Frame-Options: DENY`), `form-action 'self'`,
  `report-uri /api/csp-report`.

## How the enforcing policy was built (2026-09-15)
1. **The report-only header had never reported anywhere.** It shipped 2026-07-18 with no
   `report-uri` and no `securitypolicyviolation` listener existed, so there were no violations in
   any log to read — the retained Vercel request logs (about 24 hours on this plan) held none.
2. **So it was measured.** Headless Chromium against production, report-only header live, listening
   for `securitypolicyviolation` and console CSP messages: home at 390px and 1440px through Hourly,
   Weekly, Home, Search (typing), Settings, Sources and back; `/install` at 1440px and 390px;
   `/privacy`; `/share` in en and af; `/api/og`. Result: **0 violations and 0 external requests
   everywhere except `/share`**, where Chromium reported "Executing inline script violates … script-src"
   on both opens.
3. **`/share`**: its inline script was `window.location.replace(<JSON of the per-request URL>)` — a
   different script per request, which no hash can allow. Enforced, the meta refresh would still have
   redirected, but a refresh leaves `/share` in history and Back bounces forward again. It is now one
   constant script that reads the URL from the meta refresh, hashed into `script-src`.
4. **`api.qrserver.com`** — the open decision from the July notes. The brief for this flip was a
   policy that "permits exactly the resources production needs"; the desktop `/install` QR image is
   the one external resource production loads, and `privacy.html` already discloses goQR.me. It is
   allowed by name. Self-hosting the QR (client-side or an `/api` route) remains the stricter option.
5. No inline event handlers (`on…=`) exist in `index.html`, `install.html`, `privacy.html`,
   `assets/*.js` or `api/*.js` (git grep, 0 matches), so nothing relies on `'unsafe-hashes'`.

## Still unexercised by that measurement
- The QR image itself: headless desktop Chromium takes the Chrome install branch of `/install`, so
  the "open on your phone" card (`assets/install.js`, the `else` branch) did not render. Its origin is
  allowed; watch `/api/csp-report` for `img-src` reports from Firefox/Safari desktop.
- Real-device PWA install and Web Share sheets (Android, iOS).
- In-app browsers that inject scripts (Facebook/Instagram/TikTok webviews) — an injected script is
  now blocked and will show up as a `[pw-csp]` enforce line, which is the point of the week.

## Regenerating hashes
Inline scripts changed (index.html, install.html, or `api/_lib/share-redirect.js`)? Run
`node scripts/generate-csp.mjs --write` and commit `vercel.json`. `tests/csp.test.js` fails if
`vercel.json` is stale, so drift can't ship silently.
