[verified] Probably Weather’s live CSSOM uses `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`, with no downloaded webfonts. At 390px the hero “Probably” and range are both 44.8px/800/49.28px, the condition is 24px/700, witty line 22.4px/800, and stats 12px/600. At 1440px the Postcard voice is: location 13.12px/800 with 2.36px tracking; “Probably” 67.68px/300 with −3.05px tracking; range 97.92px/900 with −6.85px tracking; condition 34.56px/800; stats 15.04px/400. The caption declares `Segoe Print`, `Bradley Hand`, `Comic Sans MS`, cursive at 19.44px/600. Nav controls resolve to browser-default Arial (16px mobile, 14.08px desktop) because `.nav button` does not inherit the body family. Source: live Playwright CSSOM plus [`assets/app.css`](assets/app.css).

[inferred] The headline typography problem is therefore not “system fonts are always bad.” Windy remains coherent with a system stack. Probably Weather’s weakness is the combination of an undifferentiated system face, inconsistent control inheritance, platform-dependent caption fallbacks, too many 700–900 weights on mobile, and exceptionally tight range tracking on desktop. A deliberate family can add identity, but hierarchy and cascade must be corrected even if the family stays.

## 5. Prioritized recommendations

1. **Prototype one deliberate type system: Onest for UI/display, Caveat for the desktop caption.** [verified] [Onest](https://github.com/simpals/onest) is a screen-oriented variable family with 100–900 weights; [Caveat](https://github.com/googlefonts/caveat) is a variable handwritten family with 400–700 weights. Both use the [SIL Open Font License 1.1](https://openfontlicense.org/). The [Google Fonts CSS response](https://fonts.googleapis.com/css2?family=Onest:wght@100..900&family=Caveat:wght@400..700&display=swap) and referenced WOFF2 files measured on 2026-07-14 total 48,228 bytes for Onest Latin + Latin-ext and 104,404 bytes for Caveat Latin + Latin-ext; the local Sesotho copy requires Latin-ext for `š`. Load Onest once with `font-display: swap`; lazy-load Caveat only at ≥1024px, because mobile never renders the caption. [inferred] This gives the brand a reproducible voice without charging phone users the 104KB caption cost. **Effort:** M — font licensing files, subset/loading policy, CSS tokens, five-language visual gates. **Audit artifacts:** local fair-pair screenshots and evidence JSON under `output/design-wave/type-gate/`, plus the named font-loading/zero-mobile-request browser test. **Decision gate:** Al approves Onest/Caveat from screenshots before implementation ships.

2. **Fix hierarchy and cascade whether or not Recommendation 1 wins the taste gate.** [verified] Set every button to inherit the chosen UI family; stop the current Arial leak. Prototype these desktop tokens: location 13/700/0.14em; “Probably” 68/300/0.98 with −0.035em; range 98/800/0.96 with −0.045em and tabular numerals; condition 34/700; stats 15/450; actions 15–16/650; nav 14/600. Prototype mobile with “Probably” 44–48/650, range 48–52/800, condition 24/700, witty 20–22/650 and stats 12/500. Preserve “Probably” on its own line and the range nowrap contract. [inferred] The exact sizes are starting tokens for an owner gate, not proven optima. **Effort:** S–M — CSS plus geometry/language regression. **Audit artifacts:** live computed-style assertions in `scripts/verify-type-prototype.mjs`, static contract `tests/type-prototype.test.js`, and unchanged 390/360/320 geometry output alongside the three type-gate screenshots.

3. **Keep the glass-band regression fixed while judging the Postcard’s taste.** [verified] The seam was a rendering defect, not a rejected design premise. Production baseline `53f918f` neutralises only the desktop home pseudo-element and retains mobile/tablet geometry. **Effort:** implemented; regression-only. **Audit artifacts:** local `output/desktop-postcard/glass-band/` before/after set and `npm run verify:desktop` output.

4. **Give non-home desktop screens a calm, explicit state.** [verified] Keep the Postcard only on Home; when Hourly/Weekly/Search/Settings/Sources is open at ≥1024px, use the already-loaded blurred weather backdrop and one centred readable panel, without the sharp polaroid/voice showing behind it. This follows the owner’s existing ruling and fixes the live layering seen in local capture `research/smaak-run4/probably-weather/live-desktop-weekly-1440x900.png`. **Effort:** M — desktop-only state CSS plus click-through and screenshots; no mobile selectors. **Audit artifacts:** five 1440×900 non-home screenshots plus the unchanged Home Postcard and mobile geometry harness.

5. **Translate ensemble agreement into one plain-language confidence line.** [verified] The Sources screen already carries provenance; [inferred] a compact “5 sources agree” / “sources are split” line can turn hidden technical advantage into user trust without adding forecast data. Show it only when the ensemble can support the statement and make it open Sources. **Effort:** M — copy across five languages, agreement thresholds, accessibility and source link. **Audit artifacts:** exact source-count fixtures in `tests/`, five-language copy review, and Home screenshots for high/low agreement at 390 and 1440.

6. **Add source-attributed severe alerts, not a radar product.** [verified] All five leaders cover alerts; PW has no inspected alert surface. Use an on-open banner/card only for a live authoritative warning, with place, validity window, source and one details action. Permission for future push alerts must follow an explicit user choice; never prompt on first load. **Effort:** L — reliable SA alert source, expiry/dedupe, translations, offline behaviour and safety review. **Audit artifacts:** signed source contract, stale-alert tests, storm/clear browser fixtures, five-language copy approval, and a no-alert screenshot proving zero ordinary-day clutter.

7. **Instrument Share as a product funnel before changing its design.** [verified] Share is already the visual primary action on both surfaces and CARROT confirms that forecast sharing belongs in the category. Capture privacy-preserving events for Share opened, system share completed where observable, link copied, and shared-link return—never coordinates or free-form location. [theory] This will reveal whether the constraint is discovery, completion or the received card; it does not assume the current button is broken. **Effort:** M — event schema, consent/privacy review and dashboard. **Audit artifacts:** documented event contract, payload privacy tests, and a dated 4-week baseline report before any creative redesign.

8. **Adopt explicit product-spine kill criteria.** [verified] Radar, 15-day precision, weather news, collectibles and broad metric dashboards are leader capabilities, not PW requirements. Reject proposals that add a new daily job, cannot be explained in one glance, weaken “Probably” honesty, or obscure Share. **Effort:** S — product decision, no code. **Audit artifact:** a one-page `PRODUCT_SPINE.md` decision record signed by Al and referenced in future briefs.

## 6. Identity decisions surfaced for Al

1. **Webfont or tuned system stack?** [inferred] Recommended ruling: approve an Onest + desktop-only Caveat screenshot prototype. If it fails the taste gate, keep the system stack but still ship the hierarchy/cascade corrections. The evidence does not support “custom font automatically wins.”
2. **Handwritten caption face.** [verified] The concept is locked; the implementation is not reproducible across Windows, macOS, Android and Linux today. Recommended ruling: keep handwriting as identity and replace the fallback lottery with a licensed, self-hosted caption face.
3. **Gold hierarchy.** [verified] Brand gold is locked at `#ffd700`, while the live desktop condition uses warmer amber `#f5a623`. Al must rule whether amber is an intentional semantic accent (recommended: condition only) or whether every accent must converge on brand gold. Do not silently normalise it.
4. **How explicit should “probably” confidence become?** [inferred] Recommended ruling: one optional plain-language agreement line, never a faux-precise confidence percentage. It should clarify the promise, not turn the joke into a disclaimer.
5. **Severe-weather posture.** [inferred] Recommended ruling: authoritative warnings may temporarily outrank humour and Share; ordinary weather never does. This is a safety hierarchy decision, not a feature-volume decision.
6. **Desktop secondary-screen atmosphere.** [verified] Home remains the owner-approved Postcard. Al must choose whether non-home panels keep only the blurred current-weather backdrop (recommended) or retain a subdued fragment of the polaroid. The current live full polaroid behind panels is render drift, not a considered state.
7. **Health data boundary.** [theory] Air quality/pollen can be useful, but only Al can decide whether a verified single health callout belongs inside “honest weather” or dilutes it. No implementation should start before SA coverage is proven.

[verified] Locked and not reopened by this dossier: witty South African voice in five languages; real portrait-composed photo backgrounds; brand gold; “Probably” understatement; Share as growth engine; and the desktop Postcard concept.
