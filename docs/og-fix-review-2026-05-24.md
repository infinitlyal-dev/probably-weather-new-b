# OG Fix Adversarial Review Log — 2026-05-24

Companion to: `docs/promote-plan-2026-05-24.md`, `docs/promote-report-2026-05-24.md`.

Context: The first promote attempt halted at the Phase 6 test gate because `api/og.js` started feeding the newly-promoted WebPs to `@vercel/og 0.11.1` (Satori), which throws `u2 is not iterable` on certain WebP encodings. Al chose Option B: switch `api/og.js` to read pre-built static `og/<condition>.jpg` (JPEG) instead of source WebPs. This loses time-of-day variation in dynamic OG cards — invisible to users because social platforms cache per-URL for ~30 days.

---

## Round 1 — 7 findings (1 CRITICAL, 4 MAJOR, 2 MINOR)

### #1 MAJOR — REJECTED as unfounded

**Codex claim:** Unaliased emitted conditions (`snow`, `mist`, `sleet`, `freezing`, `heat-wave`, `drizzle`, `haze`) would first try a missing `og/<condition>.jpg`.

**Ground-truth verification:** Grep of `api/weather.js deriveCondition()` shows the emitted `key:` universe is exactly: `clear, cloudy, cold, cold-clear, fog, heat, rain, storm, wind, hail, thunder, uv, rain-possible, partly-cloudy`. No `snow`/`mist`/`sleet`/`freezing`/`heat-wave`/`drizzle`/`haze` keys are ever returned by the source. The condition universe is well-bounded.

Rejected with explicit reasoning.

### #2 MAJOR — APPLIED

**Codex claim:** `WEATHER_BACKGROUND_ALIASES` maps `uv → clear` and `rain-possible → cloudy`, so the dedicated `og/uv.jpg` and `og/rain-possible.jpg` files (built by `tools/build-og-images.mjs` ALIASES block) are never served. Marketing-critical specificity regresses.

**Fix:** Added OG-specific narrower alias map `OG_BACKGROUND_ALIASES` containing only `partly-cloudy → cloudy`, `hail → storm`, `thunder → storm`. `uv` and `rain-possible` pass through verbatim → `og/uv.jpg` and `og/rain-possible.jpg` are served as-is. The picker's broader `WEATHER_BACKGROUND_ALIASES` is preserved unchanged (the picker needs it because no dedicated WebP folders exist for uv/rain-possible).

### #3 MAJOR — APPLIED

**Codex claim:** Hypothetically `assets/images/bg/default.jpg` may not exist. Recommend switching final fallback to `og/default.jpg`.

**Ground-truth verification:** Both files exist: `assets/images/bg/default.jpg` (136K, May 12) and `og/default.jpg` (102K, May 28, regenerated by build-og-images). Either works.

**Fix applied for consistency:** All OG sources now live under `og/`. Final fallback switched to `og/default.jpg`. The picker's separate fallback chain still uses `assets/images/bg/default.jpg` (unchanged).

### #4 CRITICAL — APPLIED

**Codex claim:** If `renderPng` throws in the fallback path (Satori font missing, ImageResponse broken, JSX malformed), the handler crashes and Vercel returns its default 500.

**Note:** This is a pre-existing vulnerability of the prior code, not introduced by the OG fix. But codex is right to flag it as critical.

**Fix:** Wrapped the fallback `renderPng` in its own `try/catch`. On double-failure: log to console, send `text/plain` response with `Cache-Control: no-store` and status 500 body `'OG render failed'`. The handler no longer crashes; Vercel routing stays sane.

### #5 MINOR — APPLIED

**Codex claim:** `candidates = [model.backgroundPath, ...chain]` is redundant — `chain` already starts with the same path. Set dedupes it. Just confusing.

**Fix:** Removed the redundant prepend. `readBackgroundDataUrl` now iterates `getOgStaticBackgroundFallbackChain(model.condition)` directly.

### #6 MINOR — APPLIED

**Codex claim:** No case normalization. Hypothetically `conditionKey` could arrive capitalized; Linux/Vercel filesystem is case-sensitive.

**Fix:** Added `resolveOgFolder()` helper that does `String(condition || '').toLowerCase()` before alias lookup. Test added: `'Storm'` → `og/storm.jpg`, `'COLD-CLEAR'` → `og/cold-clear.jpg`.

## Round 2 — verdict SHIP

Codex round-2 review verified all 6 round-1 dispositions correctly landed in the diff:

1. #1 rejection appropriate (deriveCondition emit universe verified bounded)
2. `OG_BACKGROUND_ALIASES` maps only `partly-cloudy`, `hail`, `thunder` — preserving real `og/uv.jpg` and `og/rain-possible.jpg`
3. Fallback chain ends at `og/default.jpg`
4. Handler fallback render has its own try/catch + safe 500 text response
5. `readBackgroundDataUrl` has only one path prepend (no redundant `[backgroundPath, ...]`)
6. `resolveOgFolder()` lowercases condition input

**No new critical or major issues found.**

> **Codex verbatim:** "Verdict: SHIP. The round-1 fixes address the real failure modes: unmapped emitted conditions now resolve, existing `uv`/`rain-possible` OG assets are not accidentally collapsed, fallback points at a verified file, and the handler no longer crashes if fallback rendering fails. The remaining behavior is conservative and backed by the passing OG-path tests."
