## 5. Known bugs (REPORT ONLY — not fixed)

### 5a. Day-of-week — "Saterdagenergie" (Saturday energy) on a Sunday
**Root cause is content/selection, NOT day computation.** `getLocationDayOfWeek()` (`app.js:1183`) correctly returns the location's day via `utcOffsetSeconds`-shifted `getUTCDay()`.

The defect: `getWittyLine()` at **`app.js:1099–1100`** —
```js
if (isWeekend && (condition === 'clear' || condition === 'heat')) {
  const wl = T.witty.weekend[settings.lang] || T.witty.weekend.en;
  return wl[Math.floor(Math.random() * wl.length)];   // early return — UNFILTERED
}
```
`isWeekend` is true for Sat (6), Sun (0), **and** Fri ≥16:00. It returns a **random** line from the single undifferentiated weekend pool, and the early `return` **bypasses** the `WEEKDAY_ONLY_FRAGMENTS` filter at `app.js:1110–1126`. That pool (`weather-copy.js:156–161`, ST on the last line) contains a **Saturday-named line at index 19 in all five languages**: EN "Saturday energy: maximum. Responsibilities: minimum.", AF "Saterdagenergie: maksimum. Verantwoordelikhede: minimum.", ZU/XH "Amandla angoMgqibelo…" (uMgqibelo = Saturday), ST "Matla a…". On a Sunday the random draw can surface it. **Wrong-day source = `weather-copy.js:156–160` index 19, selected unfiltered at `app.js:1099–1100`.** (Index 22 "Boerie roll for breakfast? On a weekend?" is weekend-generic — fine.) [FIX-AFTER] (visible copy bug; reword index-19 weekend-generic across 5 langs, or split the pool Sat/Sun, or extend the filter to the weekend pool).

### Gap A — Service-worker offline shell is broken **[FIX-BEFORE-LAUNCH]** · codex-CONFIRMED
`sw.js` `CORE_ASSETS` (sw.js:21-31) precaches only `app.js`, `install.js`, `startup-location.js` (+ html/css/manifest). But `assets/app.js` statically `import`s **9** modules; the **7 not precached** — `language-preferences.js`, `weather-copy.js`, `weather-visuals.js`, `image-picker.js`, `weather-emoji.js`, `share-url.js`, `first-open-location.js` — are also **never runtime-cached**: the fetch handler's catch-all (sw.js:236) is `fetch(req).catch(() => caches.match(req))` with **no `cache.put`**, and `/assets/*.js` is served `max-age=0, must-revalidate` (vercel.json). So on **any offline launch**, `app.js` loads from cache, then its first un-cached `import` rejects → the app fails to initialize (white screen) instead of showing cached weather. This is a regression from when the module graph was smaller (the precache list wasn't updated as modules — e.g. the just-added `first-open-location.js` — were added). **Fix:** add the 7 modules to `CORE_ASSETS`, or `cache.put` same-origin `/assets/*.js` in the fetch handler. Verify with DevTools → Offline after a clean install.

### Gap B — `cold-clear` share cards fall back to default **[FIX-AFTER]** · codex-CONFIRMED
`share-url.js` `SHARE_BG_ALLOWLIST` (share-url.js:7-10) omits `cold-clear` (and it's not in `SHARE_BG_ALIASES`), so `normalizeShareCondition('cold-clear')` → `'default'`. Yet `middleware.js` `CONDITION_ALLOWLIST` (middleware.js:20) **includes** `cold-clear`, and `og/cold-clear.jpg` exists. The share-url comment says it "must mirror middleware.js allowlist" — it doesn't. Result: sharing during a cold-clear condition serves `og/default.jpg` instead of the themed `og/cold-clear.jpg`. (Refines §2: `og/cold-clear.jpg` is reachable via `api/og.js`/middleware directly, but NOT via the share-URL builder.) **Fix:** add `'cold-clear'` to `SHARE_BG_ALLOWLIST`; add a `share-bg-middleware.test.js` case.

### Gap C — `/api/share` uses loose `Number()` coord validation **[NEEDS-AL-DECISION]** · codex-CONFIRMED
`api/share.js:45-46` validates coords with `Number(value)` (in range), not the strict `parseCoord` used at the other 4 entry points. `Number('0x10')` → 16, `Number('')`/`Number('  ')` → 0 — both pass `isValid*`, where strict `parseCoord` rejects them. This is effectively a **5th coord entry point** the hardening didn't cover. **Mitigation already in place:** `callWeatherHandler` forwards the raw string into `weatherHandler`, whose own `parseCoord` (api/weather.js:28) re-rejects it before any upstream fetch — so the *weather* call is guarded. Residual: confirm `share.js` doesn't reflect the raw unvalidated lat/lon into the share HTML/OG meta. **Fix/verify:** route share coords through the same strict `parseCoord`.

### Gap D — Unreachable `/index.html` branch in middleware **[FIX-AFTER]** · codex-CONFIRMED
`middleware.js` `config.matcher` is `['/']` (middleware.js:14), so the middleware only runs for exact `/`. The guard at middleware.js:201 also tests `url.pathname !== '/index.html'`, but `/index.html` is never routed to the middleware — dead defensive branch. Harmless; remove or widen the matcher if `/index.html` interception was intended. (Note: this is the *middleware*; the SW's separate `/index.html` navigation fallback at sw.js:204 is live and correct.)

### Gap E — TWA `assetlinks.json` fingerprint unverified **[NEEDS-AL-DECISION]** · codex-CONFIRMED
`.well-known/assetlinks.json` hardcodes package `za.co.probablyweather.twa` + one SHA-256 cert fingerprint. If that fingerprint doesn't match the **actual Play App Signing** key, Android TWA Digital Asset Links verification fails and the installed app opens with browser chrome (URL bar) instead of full-screen. Can't be verified from the repo. **Fix:** cross-check the fingerprint against the Play Console's App Signing page before/at launch.

**Iteration:** all codex objections (5 gaps + 3 sandbox-unverified claims) are folded in and independently verified above. No finding was disputed. The audit is sound **with these 5 gaps added** — Gap A (offline) is the material launch-blocker codex caught that the first draft missed.
